2. **Authoritative Persistence Models (`app/persistence/models.py`):**
   - Defined 15 SQLAlchemy tables with typed columns, explicit nullability, cascades, and indexes:
     - `guardians`: Pseudonymous guardian identity, `email_hash` (`DATA-008`).
     - `children`: Pseudonymous child profile, coarse `age_band` (`4-5`, `6-8`) — strictly NO exact DOB (`DATA-008`).
     - `devices`: Doll hardware registration, unique serial, binding to child/guardian.
     - `consents`: Guardian consent tracking with status `GRANTED` / `REVOKED` (`DATA-010`).
     - `curriculum_versions`: Immutable curriculum version manifest (`curriculum-v1.0`) (`DATA-003`).
     - `curriculum_skills`: Skill categorizations within curriculum release.
     - `curriculum_items`: Approved turn prompts, expected answer token lists, and offline audio fallback IDs.
     - `sessions`: Protected by integer `state_version` for optimistic concurrency (`DATA-002`).
     - `turns`: Sequential turn execution records.
     - `attempts`: Child attempt resolutions with unique `message_id` for idempotency and replay protection (`DATA-004`). Validated text only, strictly NO raw audio/frame storage (`DATA-006`, `ADR-013`).
     - `child_mastery`: Authoritative mastery progression state (`INTRODUCED`, `PRACTICING`, `ACQUIRED`) (`ADR-011`).
     - `mastery_history`: Audit log of mastery progression transitions.
     - `domain_events`: Append-only event log (`DATA-005`).
     - `outbox_events`: Transactional outbox table committed atomically with domain events (`DATA-005`, `ADR-012`).
     - `version_metadata`: Provenance registry for curriculum, model, prompt, policy, threshold, firmware, and release (`DATA-007`).
3. **Domain Repositories & Invariants (`app/persistence/repositories.py`):**
   - Implemented normalized persistence exceptions: `OptimisticLockError`, `DuplicateKeyError`, `ConsentRevokedError`, `ImmutabilityViolationError`, `NotFoundError`.
   - `SessionRepository`: Atomic state transitions with optimistic locking (`advance_state`); blocks session creation if consent is missing or revoked (`DATA-010`).
   - `AttemptRepository`: Idempotent attempt recording; duplicate `message_id` fails with `DuplicateKeyError` (`DATA-004`).
   - `CurriculumRepository`: Forbids modifications to approved curriculum items (`DATA-003`).
   - `EventOutboxRepository`: Atomic multi-table write to `domain_events` and `outbox_events` in the same transaction; forbids event deletion (`DATA-005`, `ADR-012`).
   - `ConsentRepository`: Manages consent status and revocation.
4. **Deterministic Seed Fixtures (`app/persistence/seed.py`):**

   - Configured async `alembic/env.py` and `alembic.ini`.
   - Initial migration `alembic/versions/001_initial_schema.py`:
     - `upgrade()`: Creates all 15 tables with all primary keys, foreign keys, unique constraints, and indexes.
     - `downgrade()`: Drops all tables in strict reverse dependency order.
6. **Data Dictionary & Documentation (`docs/data-model.md`):**
